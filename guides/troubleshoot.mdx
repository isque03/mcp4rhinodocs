title: "How to troubleshoot"
description: "Fix connection, install, units, capture, and export problems"
---

Diagnose common MCP4Rhino failures and confirm the server with a shell probe.

## Prerequisites

- Rhino 8 with MCP4Rhino installed
- Access to the Rhino command line (not only Help search)

## Server and connection

| Symptom | Fix |
|---------|-----|
| Nothing listens on 4010 | Confirm Rhino is open. Open **MCP4Rhino → Status…** (Windows: under **Tools**; macOS: top-level menu) or run `MCP4RhinoStatus`. If Stopped, Start server / run `MCP4Rhino`. If `MCP4RHINO_AUTOSTART=0`, you must start manually. |
| Port bind error | Another process owns the port. Set `MCP4RHINO_PORT` and update the client URL. |
| Commands not found | Install failed, or Rhino was not restarted after install. Reinstall via Package Manager or GitHub `.yak`, then restart Rhino. |
| Claude / Cursor cannot connect | Rhino must be running and MCP4Rhino listening. Restart the AI client after editing MCP config. Confirm URL `http://127.0.0.1:4010/mcp` (or your custom port). Node.js/`npx` required for `mcp-remote`. |
| AI client on Linux, Rhino on Windows | Use the Windows host IP instead of `localhost`. |

## Units and sizing

| Symptom | Fix |
|---------|-----|
| Object is huge vs the size the user named (e.g. “32 inches” → tens of feet) | Document is likely Feet while the agent passed the inch number raw. Call `get_document_units`, `convert_length`, recreate, then `measure_size`. |
| Unit change did not resize geometry | Pass `scale_existing: true` to `set_document_units`. |

## Viewport capture

| Symptom | Fix |
|---------|-----|
| macOS capture ignores width/height | Scripted ViewCaptureToFile does not pass those into the script. Default PNG: `~/Library/Logs/MCP4Rhino/`. Embeds MCP `image` when ≤ 1 MiB. |
| Windows capture size | ViewCaptureToFile first; CaptureToBitmap fallback uses `width`/`height`. Default PNG: `%LOCALAPPDATA%\MCP4Rhino\`. |
| Path but no embedded image | Text may set `image_embedded: false` and `image_omitted_reason: "exceeds_max_bytes"`. On Windows, retry smaller size. On macOS, open `path` or reframe the view. |

## Export and license

| Symptom | Fix |
|---------|-----|
| `export_3dm` fails with a license / evaluation message | Rhino is not allowing save (`RhinoApp.CanSave` is false). Call `check_rhino_license`; renew or activate a valid license / evaluation before saving. |

## Developer updates not applying

| Symptom | Fix |
|---------|-----|
| Tools or Logic code not updating | Run hot-reload (`scripts/hot-reload-tools.sh` / `.ps1`), then `MCP4RhinoReload` / `mcp4rhino_reload`. Restart Rhino after host `.rhp` edits. |

## Logs

| OS | Path |
|----|------|
| macOS | `~/Library/Logs/MCP4Rhino/mcp4rhino.log` |
| Windows | `%LOCALAPPDATA%\MCP4Rhino\mcp4rhino.log` |

Status dialog can open the log folder. Or ask the assistant for `get_support_info`.

## Verification (shell probe)

When the server is up:

```bash
curl -sS -X POST http://127.0.0.1:4010/mcp \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
```

Or open `http://127.0.0.1:4010/` in a browser for a plain OK response.
